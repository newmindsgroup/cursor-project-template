# Contributing

## Workflow
1. Create a short-lived branch for each change.
2. Keep changes small and reviewable.
3. Update docs, decisions, assumptions, and questions as needed.
4. Use clear commit messages.

## Branching
- `main` is always releasable.
- Optional `develop` for integration if the team prefers it.

## Commits
- Use conventional commits when possible (e.g., `feat:`, `fix:`, `chore:`).
- Keep commits focused and descriptive.

## Pull Requests
- Include context, screenshots (if UI), and testing notes.
- Link related decisions, assumptions, or open questions.
- Prefer one primary change per PR.

## Review checklist
- [ ] Docs updated (brief/requirements/architecture) if behavior changes
- [ ] Decisions logged for significant changes
- [ ] Assumptions and questions updated
- [ ] Security impact considered
